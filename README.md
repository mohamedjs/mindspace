# MindSpace

**Talk. Get organised thoughts.**

MindSpace is a voice-first thinking app. You press record and talk the way you
actually think — messy, out of order, doubling back. MindSpace listens, works
out the separate ideas inside what you said, rewrites each one as a clean
sentence in your own voice, and lays them out as sticky notes you can move,
nest, group and revisit.

It is not a transcription app. A transcript gives you back the mess. MindSpace
gives you back the thinking.

## 1. What problem it solves

People think faster than they type. The moment an idea is worth capturing is
usually the moment you have no hands free — walking, driving, in the middle of
something else. So the idea either gets lost, or it gets dumped into a voice
memo that nobody ever listens to again.

Existing tools pick one side of that trade:

| Tool category | What it gives you | What it costs you |
|---|---|---|
| Voice memos | Instant capture | An unsearchable pile you never revisit |
| Transcription apps | A wall of text | Still unstructured — you do the sorting |
| Note apps (Notion, Apple Notes) | Good structure | Typing, so capture never happens |
| Mind-map tools (Miro, Milanote) | Great for arranging | You must already know what you think |

MindSpace closes the loop: **capture at the speed of speech, structure at the
quality of writing.** One recording turns into several distinct, readable notes
— each one an idea, not a sentence fragment — already positioned in relation to
each other.

## 2. Who it is for

- **Founders and operators** thinking out loud between meetings, who need the
  three decisions buried in a five-minute ramble.
- **Writers, researchers and students** developing an argument, who want to
  drill into one idea and branch it without losing the parent thread.
- **Consultants and freelancers** capturing client context immediately after a
  call, while it is still accurate.
- **Anyone who thinks better talking than typing** — including people for whom
  typing is slow, painful, or simply not available in the moment.

The product ships in an Egyptian market first (pricing in EGP, InstaPay planned
as a local rail), and handles both Arabic and English speech — the AI answers in
whichever language you thought in.

## 3. The product, feature by feature

### 3.1 Voice → sticky notes

Press the microphone. Talk for as long as your plan allows. When you stop:

1. **Transcription.** The audio is uploaded and turned into text.
2. **Idea extraction.** The AI reads the transcript and separates it into
   distinct ideas — not sentences, ideas. Two thoughts in one sentence become
   two notes; one thought spread across a minute of hedging becomes one note.
3. **Rewriting.** Each idea is written out properly: a short title and a clean,
   readable body. This is the part that makes the notes worth keeping. It does
   *not* paraphrase you into someone else — your certainty level, your slang,
   your language are preserved. It removes the "um", the false starts and the
   backtracking.
4. **Placement.** Notes land on the canvas without overlapping, colour-coded by
   type (idea, task, question, decision).

### 3.2 Sub-notes — thinking *inside* an idea

Any note can be opened and drilled into. Two ways to go deeper:

- **Type a sub-note** directly.
- **Record into the note.** The AI knows which idea you are standing inside, so
  everything it extracts is generated as children of that specific note, not
  loose on the board.

Sub-notes appear on the canvas as smaller cards orbiting their parent, joined by
animated connectors — the mind-map view of your own reasoning. You can hide
them entirely (Settings → *Sub-notes on canvas*) when you only want to see the
top-level ideas.

### 3.3 The microphone that writes the note itself

Inside a note there is a second microphone, next to the delete button. This one
does not create sub-notes — it writes **that note's own content**. Talk about
what the note means and the AI fills in or extends the body. Useful when the
title captured the idea but the substance came to you later.

### 3.4 Canvas

An infinite board you pan, zoom and drag. Six tools in a collapsible strip on
the left:

| Tool | What it does |
|---|---|
| Add a note | Blank sticky note, typed |
| Add a group frame | A titled rectangle you resize around related notes — drag the frame and the whole cluster moves |
| Tidy | Snaps everything into a clean grid |
| Fit to view | Zooms out to show the entire board |
| Recordings | Every recording made in this space, with its status |
| Show / hide sub-notes | Toggles the child layer |

Deliberately six. A tool strip that needs scrolling is a tool strip nobody uses.

### 3.5 List view and calendar

Not everyone thinks spatially. Settings → *Your notes as* switches the whole app
between **Canvas** and **List**.

List view is a conventional notes app — nested sub-notes indented under their
parents, scrollable, searchable by eye. It carries two tabs:

- **List** — grouped by day, newest first.
- **Calendar** — a month header with a week strip; tap a day to see the notes
  that belong to it. Notes with a due date appear on that date; everything else
  falls back to the day it was created, so the calendar is never empty and
  never lies about when you had the thought.

Recording is available from every view. You are never more than one tap from
capture.

### 3.6 Dates and reminders

If you say *"I need to send that proposal by Thursday"*, the AI recognises the
deadline, resolves it against today's date in your own timezone, and attaches it
to the note. That note then shows up on Thursday in the calendar and fires a
local reminder.

You never type a date. You just say when.

### 3.7 Spaces

Separate boards for separate contexts — work, a book, a client, a life decision.
Rename them, switch between them; the app remembers where you were.

### 3.8 Appearance

- Light and dark themes.
- **Hand-drawn text** — an Excalidraw-style font that makes the board feel like
  a whiteboard rather than a form. Toggle off for the system font.
- **Canvas background** — grid with soft colour orbs, or a plain solid board.
- **Sub-notes on canvas** — show the child layer, or just the parent ideas.

### 3.9 AI model choice

Settings → *AI models* lets you choose which model does the writing and which
does the listening. Sensible defaults are set; most people will never open this.
Power users and people on the *Your AI* plan will.

### 3.10 Clear errors

Every failure the pipeline can produce — out of credits, recording too long, AI
provider down, key rejected, upload failed — has a written explanation and a
suggested next action. The user is told what went wrong and what to do about it,
never a raw error code.

## 4. How to use it

### First run

1. **Sign up** with email and password, and set your name. You start with **100
   free credits** — roughly ten minutes of talking.
2. You land in your first space, on the canvas.

### Capturing a thought

1. Tap the **microphone**.
2. Talk. Say everything, in any order. Don't tidy as you go — that is the app's
   job.
3. Tap stop. Within a few seconds your ideas appear as notes.
4. Drag them where they belong. Or hit **Tidy** and let the app do it.

### Going deeper on one idea

1. Tap a note to open it.
2. To branch: tap the **microphone** and talk about that idea. New sub-notes
   attach to it.
3. To flesh out the note itself: tap the **microphone next to the delete
   button** and describe what you mean. The body fills in.
4. Close. On the canvas the sub-notes fan out around the parent, connected.

### Organising

- **Group frame** — add a titled frame, then resize it around the notes that
  belong together. Moving the frame moves the whole group.
- **Tidy** — instant grid.
- **Fit to view** — see everything at once.
- **Spaces** — start a new board when the subject changes.

### Reviewing

- Switch to **List** in Settings for a linear read-through.
- Open the **Calendar** tab to see what you thought about on a given day, and
  what is due next.
- Anything you gave a deadline to will remind you.

### Managing your account

Settings → *Account*:

- Edit your full name.
- **Plans** — see and change your subscription.
- **Your API keys** — only visible on the *Your AI* plan.
- **Sign out.**
- **Delete account** — permanently removes every space, recording and note.

## 5. Pricing and plans

All prices are **EGP per month**.

| Plan | Price | Credits / month | Roughly how much talking | Max single recording |
|---|---|---|---|---|
| **Free** | 0 | 100 (tops back up monthly) | ~11 min | 5 min |
| **Hobby** | 50 | 625 (+25% bonus) | ~69 min | 15 min |
| **Plus** ⭐ | 150 | 2,025 (+35% bonus) | ~3.8 hours | 30 min |
| **Pro** | 300 | 4,500 (+50% bonus) | ~8.3 hours | 60 min |
| **Max** | 500 | 8,000 (+60% bonus) | ~14.8 hours | 120 min |
| **Your AI** | 50 | 900 (voice→text only) | ~2.5 hours | 120 min |

⭐ *Plus* is the featured tier.

*The "roughly how much talking" column is the same calculation the app itself
shows on each plan card, so the README and the in-app copy never disagree.*

### The pricing logic

Four deliberate decisions sit behind this table:

**1. The bonus curve rewards commitment.** 50 EGP buys 625 credits; 500 EGP buys
8,000 — sixteen times the credits for ten times the price. Volume gets cheaper
because the marginal cost of serving a heavy user is lower than the cost of
acquiring a new light one.

**2. Subscriptions always beat one-off credit packs.** A 50 EGP subscription
gives 625 credits where the same money spent as a one-time purchase gives 550.
A subscription that loses to a top-up is a pricing bug, so every tier is priced
above its equivalent pack.

**3. Recording length is a real feature, not a paywall gimmick.** Free users get
5 minutes, which is enough for a genuine thought and not enough for a meeting.
Max gets two hours. Longer recordings cost proportionally more credits anyway —
the cap exists so nobody accidentally burns a month's allowance in one sitting,
and so the free tier cannot be used as a meeting transcriber.

**4. The advertised hours are conservative.** The table quotes ~9 credits per
recorded minute, while transcription alone costs 6. The gap absorbs the
extraction cost and rounds against us on purpose — a user who gets fewer minutes
than the marketing promised is a refund conversation, and refund conversations
cost more than the credits.

## 6. How credits work

Credits are the single unit of consumption. Nothing in the app is metered in
any other way.

| Operation | Cost |
|---|---|
| Voice → text | 6 credits per minute of audio |
| Text → sticky notes | 8 credits, adjusted to what the model actually cost |
| Everything else | Free — editing, dragging, grouping, reminders, spaces |

Roughly **10 credits ≈ 1 EGP** of underlying AI spend at current rates.

**Reserve, then settle.** Before a job runs, its estimated cost is held against
your balance. When it finishes, the hold is settled at the real cost — usually
less. If the job fails, the hold is released in full. **You are never charged
for a failed recording.**

**The monthly top-up is a floor, not an allowance.** On the 1st of each month
any account sitting below 100 credits is brought back up to 100. It does not
stack — an unused month does not become 200. Note that this floor applies to
*every* account, not only free ones: a paid subscriber who burns through their
monthly credits is also topped back up to 100 at the start of the next month.
That is a deliberate safety net today, but it is worth being aware of when
modelling revenue.

**Running out.** The app tells you before it starts a job it cannot pay for, and
points you at the plans screen. Nothing is lost — the recording is not consumed.

## 7. Bring your own AI

The **Your AI** plan (50 EGP/month) is for people who already pay OpenAI,
Anthropic or Google and would rather not pay twice.

**What runs on your key:** turning text into sticky notes. All of the writing,
the idea extraction, the rewriting. Billed by your provider, against your own
account limits, at your own rates. MindSpace takes no credits for it.

**What runs on ours:** turning voice into text. Every recording is transcribed
on the platform's own provider account, always. That is why this plan is not
free and includes 900 credits — about 2.5 hours of talking a month.

Two reasons for that split, both honest:

- Speech-to-text is the one step where routing your audio to a provider you only
  meant to use for text would be a genuine surprise. One predictable path for
  audio is worth more than the saving.
- Anthropic's OpenAI-compatible endpoint strips audio input entirely. A Claude
  user could not transcribe on their own key even if we allowed it.

**Supported providers:** OpenAI (GPT), Anthropic (Claude), Google (Gemini).
Nothing else. Pick one, save the key, and the model list narrows to that
company's models — so what the settings screen shows is exactly what runs.

**Key handling:** the key is stored server-side and never returned to the app.
After you save it you see only a hint (last four characters). If a provider
rejects it, the app says so and asks you to replace it, rather than silently
falling back to platform credits and charging you.

## 8. Payments

Four payment rails are built into the system behind a provider factory, so
adding a fifth is configuration rather than surgery.

| Channel | Purpose | Status |
|---|---|---|
| **TestPay** | Internal testing and demos | ✅ Working, feature-flagged |
| **Google Pay** | Android in-app purchase | ⚠️ Scaffolded — needs Play Console credentials |
| **Apple Pay** | iOS in-app purchase | ⚠️ Scaffolded — needs App Store Connect key |
| **InstaPay** | Egyptian bank rail | ⚠️ Scaffolded — needs a gateway (Paymob / Fawry / Kashier) |

Every channel is verified **server-side** before credits are granted; the app
never decides that a payment succeeded. Confirmations are idempotent — a retried
or duplicated confirmation produces one payment record and one credit grant,
verified by test.

## 9. Trust, privacy and account control

- **Your data is yours per-row.** Database-level access rules mean one account
  physically cannot read another's notes, recordings or balance — this is
  enforced by the database, not by application code that could have a bug.
- **API keys never come back out.** Stored server-side, shown only as a hint.
- **Deletion is real deletion.** "Delete account" removes every space,
  recording, note and ledger entry. Not a soft flag.
- **Deleting a note keeps its children.** Sub-notes are promoted to the parent's
  level rather than silently disappearing with it.
- **Reminders are local.** Due-date notifications are scheduled on the device.
  No server needs to know when you are busy.

## 10. What is live and what still needs setup

Stated plainly, because a launch checklist that hides its gaps is worse than no
checklist.

**Working end to end today**

- Voice capture → transcription → idea extraction → notes on canvas
- Sub-notes, including voice-generated ones, with connectors
- The note-writes-itself microphone
- Canvas with all six tools, group frames, spaces
- List view, calendar tab, due dates and local reminders
- Credits: reserve / settle / release, monthly free top-up, ledger
- The full plan catalogue and the subscription flow, via TestPay
- BYOK key storage, provider-scoped model filtering, split billing
- Themes, fonts, view preferences, account management, account deletion

**Needed before taking real money**

1. **Turn off TestPay.** The `ALLOW_TEST_PAY` flag is currently enabled on the
   project. While it is on, anyone can subscribe for free. Unset it at launch.
2. **Wire one real payment channel.** Google Pay needs a Play Console service
   account; Apple Pay needs an App Store Connect issuer ID, key ID and `.p8`
   plus the In-App Purchase capability; InstaPay needs a gateway partner. Each
   currently refuses cleanly rather than pretending to work.
3. **Automate renewal.** A subscription today grants its credits once and stores
   a period end date. Nothing advances that date, so it lapses instead of
   renewing. This needs a scheduled job before monthly billing is real.
4. **Enforce the recording cap on the server.** Maximum recording length is sold
   as a per-plan feature, but it is currently checked only in the app, which
   fails closed to the 5-minute free limit when the plan is unknown. A modified
   client could exceed its tier. Same class of gap as TestPay: it protects
   revenue, so it belongs before launch rather than after.

**Needed before shipping to phones**

5. **Build a native app.** Reminders use notification capabilities that do not
   exist inside Expo Go. A development or production build is required for
   due-date alerts to fire.

**Unverified**

6. **The BYOK provider paths have not been exercised with live keys** — no
   OpenAI, Anthropic or Google credentials exist in this project. The routing,
   filtering and billing logic is tested; the actual HTTP round-trip to each
   provider is not. Verify with one real key per provider before selling the
   *Your AI* plan.

## 11. Running the app

```bash
npm install
```

```bash
npx supabase link --project-ref <your-project-ref>
```

```bash
npx supabase db push
```

> **Note for a clean project:** there are two migrations numbered `0022`
> (`0022_default_space.sql` and `0022_note_groups.sql`). Both are already
> applied on the live project, but on a fresh database their order is
> ambiguous — renumber one before pushing to a new environment.

```bash
npx expo start
```

Deploy every edge function (`transcribe`, `ai-extract`, `ai-note-write`,
`byok-save`, `byok-delete`, `subscribe-start`, `subscribe-confirm`):

```bash
npx supabase functions deploy
```

**Architecture in one paragraph.** The app is React Native on Expo, with
Supabase for auth, storage, database and server functions. Business logic sits
behind a repository layer — the UI talks to interfaces, and the Supabase
implementation lives in one isolated folder. That boundary is enforced by an
automated test that fails the build if any screen, hook or feature imports the
database client directly. Payment providers sit behind a factory with the same
discipline: adding a rail means adding one file, not touching the checkout.
