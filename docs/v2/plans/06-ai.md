# 06 AI extraction and note writing

## Goal
Transcripts become notes. Port `ai-extract`, `ai-note-write`, `_shared/extraction.ts`, `layout.ts`, `models.ts`, `prompts/`, and providers. Prompts move verbatim. Closes H2, H6, M3, M5, M6, P1.

## Logic
- Zod in `extraction.ts` becomes Yup, with existing test cases ported from `apps/web/src/features/ai/schemas/extraction.test.ts`.
- Verify space, parent note and target note belong to the user, before reserving.
- Prompt context is capped: at most 60 notes, most recently updated first, content cut to 400 characters, always including the focus note.
- Long meetings: when a transcript exceeds 12,000 characters, split on sentence boundaries, extract per chunk with `p-limit(LLM_CONCURRENCY)`, then run one merge pass that removes duplicates and adds relations. `MAX_NOTES` is 8 for normal recordings and 40 for meetings.
- Notes, action, items, relationships, recording status and credit settlement commit in one transaction. Retrying a recording that has an `ai_actions` row with notes does not create more.
- `resolveModel`: keep the documented order; every query error is handled. Use status `accepted` for note writes. Chat calls have a 120-second deadline.
- Meeting recordings create their own space named with an AI title and the date.
- `GET /models`, preferences, and `POST /ai/actions/:id/undo`.

## Acceptance checks
Standard check with a fake provider: end to end from `finish` to notes; failure before commit leaves no notes and no charge; a retry makes no duplicates; a charge never exceeds the reservation; a foreign `spaceId` gets 404; a 200-note board still yields a bounded prompt.
