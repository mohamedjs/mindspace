# 14 Review and fix phases 08 to 12

You are the reviewer now, not only the implementer. Phases 08 to 12 were built by Gemini Flash, and checked only by builds and API tests. Nobody has reviewed the code.

## Read first
`docs/v2/plans/STATUS.md`, especially "What review found in phases 01 to 06". Those defects recurred in every phase. Also read `docs/v2/AUDIT.md`, `docs/v2/ARCHITECTURE.md`, `docs/v2/TOOLBAR.md`, and plans 08 to 12.

## For each phase, 08 then 09, 10, 11, 12
1. Compare the code with every line of that phase's plan, and list anything missing or different.
2. Hunt for the known defect classes: races, rollback traps, tests passing only on dirty state, unsafe fallbacks, unbounded input, wrong error envelopes, leaked internal errors, missing ownership checks, and tokens stored insecurely.
3. Phase specifics:
   - 08: no direct Supabase use; refresh handled once for parallel 401s; SSE reconnects; the toolbar matches `TOOLBAR.md`; no invalidation of all `['notes']`.
   - 09: minimal permissions; parts deleted only after a 2xx; resume after a browser restart; a consent notice on first use; refresh token not in `chrome.storage.sync`.
   - 10: tokens in `expo-secure-store`; `gestureOrder.test.ts` passes; `EXPO_PUBLIC_API_URL` set per EAS profile.
   - 11: no invented claims, testimonials or numbers; prices match `seed.sql`; links empty show "Coming soon"; workflow permissions are least privilege.
   - 12: Caddy passes SSE unbuffered; backups actually restore; no secrets in Compose files; containers run as non-root.
4. Fix every real defect, with a test that fails before the fix. Do not refactor working code for style.
5. Record in `notes`, per phase: defects found, fixes, tests added, and what still needs a human, such as a device or a real meeting.
